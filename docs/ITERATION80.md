# Iteración 080: trazas de `player_step` para smoke ACT_ONE

El probe C de rutas ahora puede guardar un archivo VTR1 con una muestra de botones Vita por cada tick que ejecuta `player_step`. `tools/record_act_one_route.py --trace` valida que el número de frames coincida con el recorrido exitoso y genera un proof v3 ligado al hash del VWI, VWE, simulador y traza. El empaquetador copia el sidecar VTR junto al proof y ambos quedan cubiertos por el manifiesto. El generador de replay utiliza cada traza solo si el proof y sus hashes son válidos; los pisos sin proof v3 conservan la ruta geométrica provisional.

El runtime acepta ahora hasta 1,024 segmentos VTS1 (con el límite existente de 36,000 ticks). El smoke conserva `route_sources` en `run.json` y en el reporte, incluidos fallos anteriores al inicio nativo. Esto distingue una ruta grabada con `player_step` de una estimada por tiles.

El archivo mide 830,039 bytes y su SHA-256 es `E59D9BE79CF6BC9E4B4C3D022F9BBA3FBCF052B4FC1E286A067F48F8643841A9`.
