# ACT_ONE boss reverse-engineering ledger

This ledger applies Decompedia's distinction between matching decompilation
and gameplay-oriented reverse engineering. VaganteVita currently targets an
ARM Vita port with reconstructed behavior; it does not have the original
compiler/build inputs needed to claim a byte-matching decompilation. Ghidra
pseudocode is evidence for hypotheses and control flow, not recovered source.

## Evidence discipline for the next implementation

### Worm transport audit (2026-10-18)

The earlier table's “six linked” description is inaccurate. In the local
Ghidra export for `BossWorm::setLevel` (`_local/decompiled/005307a0.c`), the
head branch loops while `local_1e8 < 0x14` and links each created crawler to the
head segment and previous body member: 20 linked crawler children. The Vita
VWE3 loader accepts subtypes 49, 50, and 51, with subtype 51 instantiating a
provisional 20-segment body rendered from the private Worm sheets. This is a
transport and visual/runtime scaffold, not a reconstructed encounter: native
state selection, patrol/path behavior, runtime spit/acid projectile, collision
and constructor damage, death/reward, and campaign flow remain unresolved.
Ghidra evidence identifies projectile type 10, poison classification, the 2.5
velocity multiplier, cooldown/count cases and sound event; their state mapping
and runtime parity are still open.
The route-history table currently has four static World-address slots; a
production-quality per-instance lifecycle remains needed if simulations need
more concurrent Worm worlds.

### Worm stats and contact damage refinement (2026-10-18)

`BossWorm::initializeStats` (`0x00530df0`) multiplies the base health and
damage scale factors by 100 and 3; in NG+ it uses 500 and 10. `Monster::Monster`
(`0x006b35f0`) initializes those factors to 1 and NG+ false, so normal Worm
stats are 100 HP and nominal damage 3. `BossWorm::doCollision`
(`0x00531d00`) rolls `damage - 1 + uniform_int(0,2)` and sets a per-player
cooldown of 30 frames. VWE3 now initializes 100 HP, and the provisional
segment-contact model uses the recovered 2–4 damage interval and cooldown.
This corrects the encounter's baseline and contact amount; crawler pathing,
exact collision trigger, shared MT19937 state, acid spit, and reward flow remain
provisional.

Each recovered function should add a record with: binary address, callers and
callees, relevant instruction/pseudocode evidence, inferred prototype and
structures, confidence, a reproducible test or trace, and the remaining
unknowns. Label a statement **confirmed** only when the binary evidence
supports it; label an implementation **provisional** when it fills a gap. Do
not report a whole-game decompilation percentage from the number of exported
Ghidra functions. A future claim of matching decompilation would need an
original-compatible compiler and binary comparison, which this port does not
currently perform.

## Gating work before boss campaign integration

1. Recover exact room/entity/enemy RNG consumption through the `addBoss` call
   site, including the native container traversal and conditional filters.
2. Validate spawn-anchor blocking against every entity category that can
   exist before the boss is added; then reproduce fallback and shuffle draws.
3. Recover each of the three constructors, stats, attacks, hit rules, defeat
   result, and level-continuation behavior. Goblin King is only one of three
   ACT_ONE boss types.
4. Recover exact boss placement and native reward/death behavior; extend the
   private package and Vita runtime with any Dragon/Worm records required by the
   recovered campaign flow. Keep provisional behavior visibly marked.
5. Verify the final-floor exit gate, boss defeat and completion screen in
   Vita3K. Host packet/route tests alone cannot prove this runtime requirement.
